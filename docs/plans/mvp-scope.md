# MVP Scope — Memory-Native Learning OS

## What "MVP" Means Here

A working prototype that demonstrates the core value proposition: **an AI tutor that remembers what you know, branches into sub-topics, tests your understanding, and schedules reviews.**

Not polished. Not production-ready. But clearly better than ChatGPT for structured learning.

---

## Phase 1: Foundation (Build First)

### Backend Core
- [ ] FastAPI project scaffold with async SQLite
- [ ] EverMemOS HTTP client wrapper
- [ ] LLM provider abstraction (start with one provider)
- [ ] Database models: ConversationNode, ConceptMastery, LearningSession
- [ ] Basic API endpoints: start session, send message, get tree state

### Agent Loop (Minimal)
- [ ] Receive user message
- [ ] Load current conversation node context
- [ ] Query EverMemOS for relevant past memories
- [ ] Assemble prompt with context + memories
- [ ] Call LLM, return response
- [ ] Store message to EverMemOS

**Milestone:** You can have a conversation and the system remembers context from past sessions.

---

## Phase 2: Branching & Tree (Build Second)

### Conversation Tree
- [ ] Create child nodes (branch into sub-concept)
- [ ] Navigate back to parent node
- [ ] Track active node per session
- [ ] Node summarization on close
- [ ] Each node gets its own EverMemOS group_id

### Frontend (Basic)
- [ ] Chat interface (send/receive messages)
- [ ] Concept tree visualization (React XYFlow)
- [ ] "Explore this concept" action
- [ ] "Back to parent" action
- [ ] Session list / history

**Milestone:** You can explore a topic, branch into sub-topics, and navigate back. The tree is visible.

---

## Phase 3: Testing & Mastery (Build Third)

### Adaptive Testing
- [ ] Feynman test: "Explain X in your own words"
- [ ] Conceptual questions generated by LLM
- [ ] LLM-based scoring across 4 dimensions (clarity, accuracy, depth, transferability)
- [ ] Test triggered after exploring a concept node

### Mastery Tracking
- [ ] ConceptMastery records created/updated on test completion
- [ ] Score history and trend tracking
- [ ] Mastery dashboard (frontend) — list of concepts with scores

**Milestone:** The system tests you after exploring a concept and tracks your mastery score.

---

## Phase 4: Spaced Repetition (Build Fourth)

### Review Scheduling
- [ ] ReviewSchedule model and logic
- [ ] Schedule reviews based on mastery score tiers
- [ ] Surface pending reviews when user starts a session
- [ ] Re-test on review, update mastery score

### Session Awareness
- [ ] On session start: check for due reviews
- [ ] Prompt user: "You have 3 concepts due for review"
- [ ] Review mode: focused re-testing of specific concepts

**Milestone:** Weak concepts automatically resurface for review. Mastery improves over time.

---

## Out of Scope for MVP

These are real features but not worth building until the core loop works:

| Feature | Why Not Now |
|---|---|
| Complex graph visualization | React XYFlow basics are enough; fancy layouts can wait |
| Multi-domain support | Start with one learning domain, generalize later |
| Peer benchmarking | Single-user first |
| Gamification | Polish, not core value |
| Multi-agent teaching styles | One teaching approach first |
| Institutional dashboard | Single-user first |
| Job readiness / CV generation | Way out of scope |
| Mobile app | Web-only for MVP |
| Authentication | Single-user prototype, no auth needed |
| Deployment | Local-only, Docker Compose |

---

## Definition of Done (MVP)

The MVP is complete when a user can:

1. Start a learning session on a topic (e.g., "Teach me Rust ownership")
2. Have the AI teach with context from past sessions
3. Branch into a sub-topic when a new term appears
4. Return to the parent topic after exploring
5. Be tested with a Feynman explanation prompt
6. See their mastery score update based on test performance
7. Come back the next day and have weak concepts surface for review
8. See their concept tree and mastery dashboard in the UI

All of this working end-to-end, even if rough around the edges.
