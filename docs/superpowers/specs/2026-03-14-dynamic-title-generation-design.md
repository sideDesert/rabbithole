# Dynamic Thread Title Generation

## Problem

Thread titles are currently set to the first 100 characters of the user's initial message (`title=req.content[:100]`). This produces titles like "I want to learn about quantum mechanics and understand..." instead of concise, descriptive labels. Only branch threads get LLM-generated titles.

## Solution

Generate better titles at two points in the thread lifecycle:

1. **After the first LLM response** — use a short LLM call to produce a 4-8 word title from the initial exchange
2. **After plan creation** — rename the thread to the plan's topic name (no LLM call needed)

Both updates are communicated to the frontend via a new `title_update` SSE event.

## Design

### Backend (`backend/app/api/chat.py`)

**New prompt constant:**

```python
TITLE_GENERATION_PROMPT = """\
Generate a concise title (4-8 words) for this learning conversation. \
Return ONLY the title, no quotes or punctuation wrapping."""
```

**New async helper:**

```python
async def generate_thread_title(user_msg: str, assistant_msg: str) -> str:
```

- Truncates both inputs to 300 chars to keep the call fast
- Calls the LLM with `TITLE_GENERATION_PROMPT` + truncated messages
- `max_tokens=30` to keep it snappy
- Post-processes result: strips leading/trailing quotes and trailing periods
- Caps output at 80 characters as a safety net
- Returns the generated title string, or the original `user_msg[:100]` on failure

**Trigger 1 — First response** (inserted after step 9, save assistant response):

- Condition: `len(history) == 0 and not thread.get("parent_thread_id")` — only fires for root threads on their first message. The `parent_thread_id` guard prevents overwriting branch thread titles that are already generated by `_compact_branch_summary`.
- Calls `generate_thread_title(req.content, full_text)`
- Yields `title_update` SSE event
- The MongoDB title update is folded into the existing step 13 `update_one` call (alongside `updated_at` and `token_usage`) to avoid an extra database round-trip.

**Trigger 2 — Plan creation** (inserted in step 11, after `new_topic_slug` is set):

- Condition: also guarded with `not thread.get("parent_thread_id")` for robustness, even though branch threads currently start in teaching phase and won't trigger `create_plan`.
- Reads the plan file, parses with `parse_plan()` to extract `tree.topic`
- Sets the title for the step 13 update
- Yields `title_update` SSE event
- No LLM call — the topic name from the plan is already a clean label

**Latency note:** The `generate_thread_title` LLM call is awaited inline in the stream. This adds ~200-500ms before the `end` event on the first message only. This is acceptable — the user just received a full streamed response, so a brief delay before `end` is not noticeable. Keeping it inline is simpler than a background task and allows us to emit the `title_update` SSE event directly.

**SSE event format:**

```json
{"type": "title_update", "title": "Quantum Mechanics Fundamentals"}
```

### Frontend

**`client/lib/api.ts`** — Add to `SSEEvent` union:

```typescript
| { type: "title_update"; title: string }
```

**`client/hooks/use-chat.ts`** — New case in SSE switch:

```typescript
case "title_update":
  queryClient.invalidateQueries({ queryKey: ["threads"] });
  queryClient.invalidateQueries({ queryKey: ["thread-tree"] });
  break;
```

This causes the thread list and sidebar tree to refetch, picking up the new title from the API.

## Edge Cases

- **LLM failure on title generation**: falls back to original `req.content[:100]` title, no error surfaced
- **Plan file missing after `new_topic_slug` set**: skip title update, keep existing title
- **Branch threads**: both triggers guard with `not thread.get("parent_thread_id")` to avoid overwriting titles from `_compact_branch_summary`
- **Subsequent messages**: title generation only fires on first message (`len(history) == 0`) and plan creation — no redundant renames
- **Short first messages** (e.g., "hi"): title will be generated from minimal context, may produce a generic title — acceptable, will be overwritten when the plan is created
- **Malformed LLM output**: post-processing strips quotes and trailing periods; output capped at 80 chars
